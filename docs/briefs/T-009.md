## Do
1. Sheet tabs exactly as the card lists (Identity & life … Lore & author notes). Basic/advanced views edit the same record.
2. Closed lists: 28 traits (pick 2–4, unique), 12 gift categories (liked/disliked disjoint; explicit item taste overrides category), 5 experience levels `none|first_encounter|occasional|recurring|extensive`, null = unassigned (not none).
3. Body map, 10 regions: `face, lips, neck, arms_hands, chest, back, belly_waist, hips_butt, thighs_legs, intimate`. Each has sensitivity 0–3 or null, and limit `ok|ask_first|never` or null. `never` wins over everything. Null never becomes 0 or ok.
4. Behaviour rules = typed event→condition→effect rows + prose notes (stored and validated only; not executed yet). Social links accept actor IDs or external names with relation/notes. Routine = weekly grid + exceptions, stored alongside existing schedules (do not replace the live schedule module).
5. Import existing actor/profile data by actor ID without loss; save → load → save is byte-stable for unchanged data. Validate duplicate IDs, unknown references, bad list values, contradictory limits.
6. Do NOT invent character content: anything not in the campus mapping stays empty/null. No extra model call per turn. Existing mechanics and consent checks unchanged.

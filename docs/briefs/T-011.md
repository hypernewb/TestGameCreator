# T-011: Day-planner mode (creator option clock | planner) (build, thin slice)
Role: implementer · Platform: codex · Milestone: O2

## Goal
In planner mode the day has 3 slots (morning, afternoon, evening). The player picks one activity per slot from a menu of what is legal and known. Ending a chat returns to the planner instead of ending the day.

## Read only
- `docs/design/day-planner.md`: the spec. Every number is in Owner decisions (campus = planner, 3 slots, 1 activity = 1 slot including travel and the chat, goodbye does not end the day in planner).
- `docs/map/README.md`, `docs/map/engine.md`, `docs/map/modules.md`, `docs/map/public.md`: find files here, then open only what you need.

## Do
1. Pack `timeMode: clock | planner`. A missing field means clock (legacy); campus is planner.
2. Build a deterministic menu from legal activities, offered scenes and waits, with no generation call. Selecting one runs the existing action/effects and consumes the current slot once. Recheck availability on arrival; an unavailable choice gives no reward.
3. Slot transitions, schedules, promise deadlines and daily limits all use the shared clock. Rollover happens after the evening slot. Save/load keeps slot progress, and retries never double-charge.
4. Do not reveal undiscovered whereabouts on the menu.
5. Tests: 3 slots consumed then rollover; a chat ending returns to the planner (planner mode) but ends the day (clock mode); an unavailable arrival gives no reward; save/load; legacy pack unaffected.

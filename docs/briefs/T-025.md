# T-025: No dead ends: refusal object with reason + alternatives (build)
Role: implementer · Platform: codex · Milestone: O2 · Fun-gate rule "No says no without a way forward"

## Goal
Whenever the engine refuses or can't do what the player typed, the player gets an in-story reason and 1–2 alternatives as buttons. After repeated retries of the same refused thing, the story redirects instead of repeating the refusal. No player-facing system error strings remain.

## Do
1. One `refusal` object: `{code, reason, alternatives:[{label, input}], retry}`. `reason` is short in-story wording keyed by code (no stack/system text); `alternatives` are valid actions computed from current state (e.g. a softer act, a different place, ask first, wait). Always ≥1 alternative.
2. Track retries of the same refused code+target within a scene; on the 3rd, return an in-story redirect (she changes the subject / the scene moves on) instead of the same refusal.
3. Replace every fixed player-facing error string on the play path with a refusal object. Add a test that scans the play path's player-facing outputs for the old strings.
4. Accept refusal codes from other modules (including future `limit_never`, `limit_ask_first` from T-024) with a generic fallback wording.
5. Refusals never change consent or eligibility. No extra model call.

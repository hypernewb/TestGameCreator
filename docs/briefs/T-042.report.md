Deviations:
- `public/campus.mjs` and `public/play.html` are not in "May change" (that lists `play.mjs`, `public/*.css`, the messages API route). I added one additive export to `campus.mjs` rather than re-deriving `modules['social.phone']` raw state inside `play.mjs` (that module is the documented mirror for exactly this), and the panel markup to `play.html` because the Rules line names "play" as additively editable and every other panel is a play.html dialog. Nothing existing in either file was changed beyond the import line and the nav row.
- No API route was added: the typed reply reuses `/api/action` and accept/read reuse engine actions from `current.actions`.
- Decline is presentation-only. There is no decline command, and `social.replyMessage` is wrong here: T-030's `replied()` marks *any* reply to a pending plan as `accepted` and emits "X waits for you at <place>", so even a raincheck would tell the player she is waiting. Declining therefore records the pass in panel state (per campaign, cleared on reload) and the invite stays pending and expires on the engine's own clock. Pinned by a test.
- A typed reply is a story turn, so it is not written back into the thread; the panel stays a mirror of engine thread state and her answer arrives in the scene. The engine's one-tap authored replies stay where they were, in the hub Phone tab.

Noticed:
- `packages/modules/phone.mjs` `actions()` only walks `thread.slice(-6)`, so an unexpired pending invite older than the six newest entries gets no Accept button at all (the panel then shows the invite with no buttons rather than inventing one).
- `social.acceptPhoneOffer` is not in `RULES_ONLY`, so accepting an invite spends a normal narrated turn; only reading is free of a model call.
- `public/campus.mjs` `phone()` sorts threads by unread while the panel sorts by recency; both now coexist (hub tab vs panel).
- `assets/showcase/ui-icons.svg` has no phone/message glyph (auto, book, check, close, history, menu, next, retry, send), so the nav Messages button is text + badge only; adding an icon means editing that asset.
- The full thread log is uncapped and scrolls (`max-height:46vh`); a 28-day run tops out around 200 entries.

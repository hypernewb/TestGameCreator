# T-046: Friends install check
Role: implementer · Platform: opencode-openrouter · Milestone: F1

## Goal
A friend on Windows with nothing installed can download the game, double-click one file and reach the first-run setup (T-044). The README has a short "Play it" section for non-developers.

## Read only
- `README.md`, `Start-Windows.cmd`, `Start-Desktop-Windows.cmd`, `start.sh`, `package.json`, `electron/`; then only what you need.

## May change
- the start scripts, `README.md` (a new "Play it" section at the top; leave the rest), `package.json` scripts (additive), `scripts/doctor.mjs` (new), `tests/install-check.test.mjs` (new); report.

## Do
1. `scripts/doctor.mjs` (`npm run doctor`): checks Node version (>=24), dependencies installed, data folder writable, port free; prints plain fixes. It never reads the contents of `data/ai-settings.json` (existence check only).
2. Windows start scripts: if Node is missing or too old, print a plain message with the download link and pause instead of flashing closed; if `node_modules` is missing, run `npm install` once; then start and open the browser / desktop app.
3. README "Play it": 5 steps max, links to getting a free Gemini or OpenRouter key.
4. Report what a packaged installer (electron-builder portable .exe) would take (size, steps), but don't build it.
5. Test: doctor reports each failure case with a fake environment; start scripts contain the Node check (a static test is fine).

## Rules
- Missing pack field = legacy behaviour. Additive edits only in shared files (server, app, play, providers, contracts); no reformatting.
- No extra model call per normal turn. Engine judges, model narrates.
- NEVER open or write `data/ai-settings.json`. Tests and experiments use `createApp({dataPath})` with a temp dir or `:memory:`.
- Never put real API keys in code, tests, fixtures or logs; use obvious fakes like `test-key-123`.

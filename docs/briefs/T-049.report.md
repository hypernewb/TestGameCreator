## How each item works

1. **recentActions dedup** — the `filter/slice(-10)/map` chain became one loop that skips `core.patch`, the score-event set, anything the actor cannot see, and any `payload.text` already taken, then slices the last 10 of what is left. Same filters, same chronological order, same fields (`source`/`tick`/`type`/`text`); the first event of a repeated pair is the one kept, exactly as T-041's `outcomes` loop keeps the first. `daypart.mjs`'s `recentActions.slice(-5)` therefore still reads oldest-first, and `service.mjs`'s `contextSources` still lists a real event id.
2. **STAGING** — the three example objects are gone; the sentence now stops at "in their hands". `One prop per beat.` is the only prop the prompt names. `INITIATIVE` still says "they stand, pick something up, take out a phone or propose a plan" — that is a cast-less action list, not a prop held by every present character, and it is what the brief left in place.
3. **Venus port** — `venusStylePrompt.mjs` imports the five exports from `scenePrompt.mjs` instead of restating them, so there is one copy of each string. The three rules sit under `Character keys that may speak:` and are gated on `cast.length`; the two user lines sit between the cast/NOT HERE block and `NOW`, each only when the engine state has it. The existing `.filter(x=>x!==undefined&&x!==null&&x!==false)` drops the `false` from the gate, and the two user lines are spread conditionally so an empty string never lands in the join.
4. **Tests** — the four new tests run on the real committed scene with the mock probe provider; the venus one also drives `CompatibleProvider` with `scenePrompt=venusStyleMessages` and asserts the five lines are in the request body that goes over the wire. The token helper strips each rule by text, not by line, so the budget still counts a rule that a later edit folds into an existing paragraph: the test moves the three system rules into the `Character keys` line and asserts the text measure still charges all 35 while a whole-line measure under-counts by 16.

Deviations:
- The dedup keeps the *first* event of a repeated pair, not the newest, to match T-041's `outcomes` loop and to leave `recentActions` in the order the daypart job and `contextSources` read it. The rendered text is identical either way; only `source`/`tick` differ.
- The three rules in the venus system prompt are gated on `cast.length`, exactly as in `scenePrompt.mjs`: a solo scene gets none of them. The brief did not say which gate to use, and the two builders should not diverge.
- The venus `NOW` line still prints `Friday 2026-10-02, Morning.` beside the new `Day 5, Friday.` line, so the weekday now appears twice in that variant. It is a faithful port of what T-041 shipped; folding `NOW` into the calendar line would be a rewording of T-041's line, which was out of scope here.

Noticed:
- `recentActions` dedup runs over the whole event log every turn, as the old `filter` already did. The ledger walk above it has an early-exit comment about not scanning the whole campaign; this loop has the same exposure and no early exit (a `Set` over the last N ids could stop it, but the old code scanned everything too, so this is not a regression).
- The dedup cap still bites: ten distinct texts are kept, so a turn that settles a lot of duplicates now reaches further back in time than before.
- `venusStylePrompt.mjs`'s system join uses `.filter(x=>x!==undefined&&x!==null&&x!==false)`, which does not drop `''`. Any future port that adds a possibly-empty string to that array silently adds a blank line; the two lines added here are spread conditionally to avoid it.
- The T-041 `AWAY_GROUPS = 2` cap still applies in the venus arm: Abigail (Hewett Gym) is left out of the list and covered only by `Absent NPCs stay put.`
- `tests/prompt-ab.test.mjs:52` asserts `/STAGING: Give each present character one physical object/`; it still passes because the instruction is untouched. Nothing in the repo asserted the removed examples.

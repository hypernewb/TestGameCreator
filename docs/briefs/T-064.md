# T-064: Scene prompt slimming — relevance-filtered injection + prose state
Role: engine refactorer · Milestone: prompt-quality (owner decision 2026-10-02)

## Goal
The hybrid scene prompt carries ~4,200 input tokens where the venus-shaped prompt does the same job in ~2,700. Most of the difference is bookkeeping the current scene cannot use. The prompt should only contain what this turn's scene can use: the present cast's info, and everything else relevance-filtered. Input is prose (cheap, readable by a small model); the JSON contract on the OUTPUT side stays exactly as it is.

## Owner constraints (fixed)
- Never send info about characters who are not in the room, beyond the one-line "absent characters" list (names only). No absent-cast dating rows, npcRelationships, rumors or pastScenes about them.
- State rendered as prose, not `JSON.stringify` — the model reads prose; the engine still parses the model's JSON output. Nothing about the output schema changes.
- `data/ai-settings.json` is off-limits; tests use `:memory:` or temp dirs.

## Milestones — implement in order, one-turn A/B sample after each, stop and report if a sample regresses
**M1 — diagnostics.** `--explain-prompt` flag on prompt-ab: per prompt block (rules, state, each pool, history, direction), print a token estimate (chars/4) per turn to the console log and a totals line in the report. This is the measuring stick; every later milestone quotes it.

**M2 — cast isolation + filter-before-inject (biggest win).**
- The state block may only describe present cast: no rows for absent characters in dating, npcRelationships, romanceNetwork, nearbyBonds, rumors, pastScenes. Absent names stay in the existing one-liner.
- Relevance-filter every pool against the current action + staged cast + location: memories, facts, generatedFacts, lorebook, openThreads, rumors, pastScenes. Reuse `relevance()`. Low bar (a shared actor or 2+ content stems gets in), cap each pool (start: 4), always keep the most recent entries when over cap. `[]`/omitted when nothing matches.
- Deduplicate: with filtering on, each memory/lore/fact appears at most once (RELEVANT MEMORY merges into the filtered pools; no double pass).

**M3 — prose state.** Replace the CURRENT STATE JSON dump with dense prose blocks in the venus style (CAST / NOW / WITH THE READER / REMEMBERED / LOOSE ENDS). Same facts, no keys/braces. Keep a machine-checkable rendering so existing prompt tests can pin phrases (assert on words, not JSON).

**M4 — two-tier state.** Items, equipped, money, actTags plumbing and other mechanical fields enter the prompt only when the action, staged cast or an active event touches them (e.g. money line only when paying/gifting is mentioned or a committed outcome involves it). The always-present core: present cast, location, time, present-cast relationship stage, scene history, direction.

**M5 — rules merge (risky, A/B-gated).** Collapse the overlapping rule paragraphs (core contract / CHARACTERS / STAGING / frameworkLength / OUTPUT CONTRACT examples) into one tight contract. Hard rules: every current hard rule survives with equal or stronger wording (POV opening, anti-exit, talk-with-not-at, no fragments/splices, spark clause, JSON contract priority). If the one-turn samples show any regression, revert M5 and report — the other milestones stand alone.

## Rules
- Existing assertions are never weakened; update pins only where the pinned phrase legitimately changed (entry-count pins stay `5–7`).
- Static prompt content stays before changing content (persona/rules first, state/action last) so local prefix caching keeps working.
- No new model calls; this is prompt shaping only. `npm run fun` and the fun gate must stay green.
- One-turn A/B command per milestone: `node scripts/prompt-ab.mjs --endpoint http://localhost:1234/v1 --model qwen/qwen3.8-27b --variants venus,ours --turns 1 --scenario roommate --seed 7` (reroll seed only if the cast schedule makes the sample useless).

## Acceptance (all)
- After M2–M4: prompt tokens for a mid-campaign turn down ≥30% vs the 4,204 baseline in the M1 report; zero absent-character data rows in the state block (asserted in a test).
- Output quality holds: word count within venus ±20%, POV opening + interleaved beats present in samples; final full check `node scripts/prompt-ab.mjs ... --variants venus,ours --repeats 2` does not regress vs the 2026-10-02 baseline report.
- New tests: absent-cast exclusion, pool caps, prose-state pin, explain-prompt totals line. `npm test 2>&1 | tail -8` no new failures.
- Report `docs/briefs/T-064.report.md` with per-milestone token deltas, artifacts paths, Deviations / Noticed / Questions.

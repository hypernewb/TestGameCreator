# T-072: Studio coverage check (every pack option has a creator control)
Role: analyzer · Platform: opencode (deepseek-v4.1-flash) · Milestone: Creator portability

## Goal
List which pack options a creator can actually set in Studio and which are code/JSON-only, and lock that in with a test so new mechanics can't ship without a control.

## Read only
- docs/roles/analyzer.md, public/studio.mjs, packages/contracts/index.d.ts (pack option types), packages/modules/*.mjs (`validate` functions show the options each module reads), packs/campus.json, packs/template-campus.json.

## May change
- docs/research/studio-coverage.md (new), tests/studio-coverage.test.mjs (new). Nothing else.

## Do
1. Inventory every top-level and nested pack option the modules read (from `validate`/contract types).
2. For each: Studio control exists? (file:line in public/studio.mjs) · set by a template? · default.
3. Write the table to docs/research/studio-coverage.md; mark each row `control` / `json-only (intended)` / `GAP`.
4. tests/studio-coverage.test.mjs: assert every option key is either found in public/studio.mjs or listed in an explicit `JSON_ONLY` allowlist in the test with a one-line reason. GAP rows go in a separate `KNOWN_GAPS` list so the test passes today but fails if a new option appears unlisted.
5. docs/briefs/T-072.report.md: Deviations / Questions / Noticed, plus the GAP list ordered by creator impact.

## Goal
Create a browser-safe, pack-independent contract that accepts existing version-1 UI wizard exports, resolves device geometry, and loads a selectable skin with a safe legacy fallback. This is infrastructure for every compatible creator-generated game; it does not yet alter the live player or creator persistence.

## Contract
- Existing export input: {format:'vn-ui-studio', version:1, units, config, css}. Validate the actual current model shape; do not invent a parallel config schema. Retain per-device layouts/constraints and independent button states. Raw css is never executed; consume validated config/style tokens only.
- Export validateSkinExport(raw): {ok, skin, warnings, error}, where skin is a cloned normalized v1 export, or null on failure; never mutate caller data. Unknown format/version and unsafe values fail, optional unsupported widgets are noted and omitted from the supported binding map rather than bound to preview values. Support future versions only through explicit validators; no silent coercion of version 2 into 1.
- Export resolveSkinLayout(skin, {width,height,device}): validated core-widget rectangles/styles resolved against the supplied stage using existing wizard constraint semantics; no hardcoded actor, pack or campus IDs. Device choice uses existing wizard rules; if none are defined, report the contract gap rather than invent thresholds.
- Export loadSkin(selection, {fetchJson,legacy}): resolves an explicit legacy selection or a versioned same-origin skin/export selection using injectable fetch; returns selected normalized skin or legacy fallback plus diagnostic. Failed loads never mutate stored selections. No localStorage, API writes or model calls inside this module.
- Generic selection envelope v1: {version:1, mode:'legacy'} or {version:1, mode:'wizard', export:<validated v1 export>}; loader may support a validated same-origin source URL in place of inline export, never both. This is an in-memory adapter API, NOT approval to introduce a project-schema field. Persisted representation must be reconciled by T-089 before creator integration.
- Supported first bindings: dialogue, input, clock/location, navigation, feedback. Module describes presentation only; receives geometry/selection, not state mutations or preview/sample characters. Unsupported optional features remain unbound.

- wizard-layout-device-parity: core rectangles and independent states match existing wizard rules at 1440/768/390 viewport widths; anchors resolved against supplied stage; long/empty/loading/error presentation variants retained. No DOM/browser usability claim from pure tests; T-084 supplies browser proof.
- wizard-pack-independence: identical valid skin loads with campus-shaped and arbitrary non-campus fixture metadata, and absent optional panels produce no fabricated data. No pack/actor/location identifiers required. No creator-proof world product task revived.

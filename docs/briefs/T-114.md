# T-114: Context hygiene + local speed
Role: implementer · Platform: codex (planned) · Milestone: CQ-A

## Goal
The prompt carries what she would remember, not engine noise, and local turns start faster.

Fixes from the Selma session:
- memories store the raw command ("Touch her hand while you flirt with her") instead of what happened;
- JSON blocks leak into the context;
- location text contradicts the scene.

Also put the static prompt prefix first, so LM Studio can reuse its KV cache.

## Do
1. **Memory.** Memory writes summarise the intent and outcome ("you touched her hand while flirting; she didn't pull away") instead of storing the raw input. Existing memories are untouched (no migration).
2. **No JSON.** Strip JSON and state dumps from the narrative context. Structured state belongs only in its compact state section.
3. **Location.** The scene's location line comes from the current state. Drop stale location paragraphs.
4. **Ordering.** Put stable sections first (rules, persona, character sheet, speech) and volatile ones last (recent turns, state, this turn). Measure with the Chat Lab's latency numbers (T-107) on local, and report time-to-first-token before and after (local run only with the owner's OK).
5. **LM Studio cause: report, don't change.** The likely owner-side cause is that `n_gpu_layers` was forced to 999999, so the memory-fit check was skipped and VRAM probably spills. Recommend offload, context and quant settings in the report only. Never touch data/ai-settings.json.

## Acceptance
- Unit tests:
  - a memory entry from a command turn contains no raw imperative;
  - the assembled narrative context has no `{`-JSON blocks;
  - the location line equals the state's location;
  - section order is stable across turns: the prefix hash is identical from turn to turn when only volatile parts change.
- `npm test` is green.
- Local time-to-first-token numbers are in the report, if the owner OKs a run.

# T-116: CP0 read-only progression trace
Role: analyzer · Platform: codex · Milestone: CP0 ([roadmap](../NEXT-MILESTONES.md#character-progression-milestones-2026-10-08))

## Goal
Record, without changing behaviour, how the existing progression signals (trust, bonds, dating phase, stage label, experience cue, memories) move across a scripted multi-encounter run on a shipped pack and on a generated route pack. This gives the owner evidence to review. It is not a fun claim.

## Do
1. Check the base: `git rev-parse --short HEAD` must print `e4816ed`. Run `npm install` only if `node_modules` is missing (declared dependencies only).
2. Write `tmp/cp0/trace.mjs` using `GameService` on a temp DB (`createApp({dataPath})` in a temp dir) or `:memory:`. NO model calls: no provider, no LM Studio, no network. Drive the game with scripted commands only.
3. Run two packs: (a) the shipped campus social pack, (b) a generated route pack. Use an existing generator or fixture in `tests/`; do not add one. At least 3 encounters per pack, including at least one non-talk scene. Reach a dating/tempo milestone if the path allows.
4. After each encounter, record: trust, bonds, dating phase, stage label, experience cue, memories. For each value, cite the `file:line` that computes it.
5. Trace the dating/tempo milestones and the breakup/settlement paths. For each, say whether the run reached it. If not reached, say why.
6. Export state, import into a fresh DB, replay the same commands. Compare. Print `replay: identical` or list the differing fields.
7. Write `docs/research/cp0-progression-trace-2026-10-08.md`: one table per pack (rows = encounters, columns = signals), the replay result, the milestone/path reachability list, and a "Not verified" list.
8. Write `docs/briefs/T-116.report.md` (about 10 lines): Status, Base, Files, Test line, Deviations, Questions.

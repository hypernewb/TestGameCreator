## Conflicts between docs
- **Milestone Order:** `design-interview.md` (line 103) states order M0 → M3 → M2 → M5, while `NEXT-MILESTONES.md` (line 15) states a re-planned order O2 → C1 → Fun gate → F1. `NEXT-MILESTONES.md` is newer and explicitly linked as the roadmap in `GAME-DESIGN.md` (line 7), so it supersedes the `design-interview.md` order.
- **Fiction vs. Game Gates / Stat Mechanics:** `venus-university/playtest-transcript.md` (line 83) notes "the narrator's warm reactions and the gate disagree" in Venus, where the LLM is unaware of gates. In contrast, `system-priorities-2026-10-01.md` (line 59) desires "meaningful progress through behaviour and a concise reaction" and `GAME-DESIGN.md` (line 91) specifies "The narrator's brief carries her likes and limits privately, so her reaction in the prose matches the verdict," indicating our game aims to avoid this divergence.
- **Pure typing vs. Activity/Menu buttons for actions (clarified):** `system-priorities-2026-10-01.md` (line 178) states the owner wants "no gameplay/action buttons" during conversations for natural flow. However, `GAME-DESIGN.md` (line 67) describes "Activity (work, gym, study)" scenes with "a quick minigame" or "result card", and `GAME-DESIGN.md` (line 55) along with `loop-comparisons.md` (line 5) mentions a "map plus phone hub". This is not a direct conflict but a scope clarification: "no gameplay/action buttons" refers to direct conversational actions, not UI elements for non-conversational activities or navigation.
- **Visual Feedback for Likeability:** `GAME-DESIGN.md` (line 107) explicitly states "We deliberately use hearts, not Venus's hidden score with a star flash, so the game doesn't read as a copy." This is a decided difference from `venus-university/findings.md` (line 29) which observes Venus using a "small flash of stars".

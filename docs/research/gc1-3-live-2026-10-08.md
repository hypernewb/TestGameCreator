# GC1.3 live typed-speech evidence (2026-10-08)

Scope: the reading loop's typed-speech path through the real `GameService` and `CompatibleProvider` against LM Studio, not mock providers. Script: `artifacts/gc1-3-live/run.mjs`; raw rows: `artifacts/gc1-3-live/results.json`. Storage was `:memory:`; `data/ai-settings.json` was not read or written.

## Run

- Model `qwen/qwen3.8-27b` at `http://localhost:1234/v1` (the test model named in CLAUDE.md), `maxTokens` 1200, timeout 180 s.
- Pack `packs/neutral.json` (world.schedule removed, as in the regression tests). Three typed-speech turns with quotes, an em dash and an emoji (turn 1), a quiet line (turn 2), and a question (turn 3).

## Result

| Turn | Fallback | Failure code | Typed line exact | Typed line index in player page | Time |

| live-1 | no | none | yes | 1 | 43.7 s |
| live-2 | no | none | yes | 0 | 11.2 s |
| live-3 | no | none | yes | 0 | 14.8 s |

- All three typed lines were saved with their exact words and no fallback, so no retry was needed.
- The typed line's speaker in the saved turn is `''`; `playerLines` maps it to the player id. This script does not assert the mapped speaker itself. The mock-provider pins do.
- Typed line index 1 in turn 1 means the NPC's opening line came first. The typed line was not folded into the NPC reply.

## Limits

- Three turns, one model, one scenario. Not a sustained campaign and not a quality judgement; owner review decides experience quality.
- The browser reading loop against the live backend was NOT run. Browser suites still use mock providers, and the live-backend read-only Creator case remains skipped (`STORY_UI_STARTUP_BASE` unset).
- Retry on live failure was not exercised, because no turn fell back.
